# F9.3 Implementation Plan -- Fixture Migration and Audit Closure

## Premises verified

1. ADR-008 already records a metadata-only audit of the private `agent-memory` repository. The
   product must not read, clone, copy, import, or publish its contents as part of F9.3.
2. F9.2 episode records are private, immutable, scrubbed, bounded, and path-free in their public
   summaries. A migration adapter must preserve those same constraints rather than add a raw-file
   importer.
3. A normal `remember` mirror is intentionally best-effort after its primary durable write. A
   fixture migration is a separate, explicit local operation and must be recoverable if a process
   stops between creating a deterministic episode and updating its migration ledger.
4. Workflow/skill content, daemon federation, MCP, provider routing, tmux session capture, and
   personal repositories are out of scope. F9.3 is a migration-proof and documentation-closure
   phase, not a live data move.

## Decision

Add an internal, test-only `cli/episode-migration.ts` adapter. It receives an already-materialized
synthetic fixture array in memory; it accepts no input path, directory, command, environment,
remote URL, transcript, or provider data. There is no `ebrain import`, `ebrain migrate`, or TUI
action in this phase.

Each fixture must have only:

```text
schema_version, fixture_id, kind, occurred_at, project, agent,
optional session, optional generated workspace_id, text
```

Unknown fields and duplicate fixture IDs fail closed. The adapter applies the shared episode text
scrubber and safe identity rules, maps fixture records to the explicit persisted source
`legacy-import`, and uses the fixture's historical timestamp. A synthetic fixture is never a claim
that eBrain has read a real legacy record.

### Deterministic recovery ledger

A private `episode-migrations/legacy-fixture-v1.json` ledger maps only:

```text
schema_version, source, entries[{fixture_id, input_hash, episode_id, imported_at}]
```

The ledger contains no text, raw source location, local path, command, provider, model, or secret.
It is `0600` in a `0700` directory and written atomically. A deterministic UUID-shaped episode ID
derives from the canonical fixture hash. Therefore:

1. A normal rerun finds a matching ledger entry and returns the original episode as `skipped`.
2. If the episode write succeeded but the ledger write was interrupted, a rerun finds the exact
   deterministic existing episode, verifies every normalized field/text, repairs the ledger, and
   returns it as `skipped` rather than duplicating it.
3. If a fixture ID's canonical input hash changes, or an existing deterministic episode does not
   match, the migration fails closed. It never overwrites either record.
4. A batch is intentionally per-record recoverable, not falsely advertised as one cross-file
   transaction. A later rerun resumes completed records and processes only remaining valid ones.

## Non-goals

- No CLI subcommand, no arbitrary import path, no automatic discovery, no live migration of
  `agent-memory`, no public export format, no raw terminal/session import, and no daemon indexing.
- No direct edit of the private repository's README or data. F10 owns clean-install public docs;
  any private-repository cleanup requires a separate reviewed change.
- No autonomous state transition, procedure capture, skillification, provider/model selection,
  external memory backend, or LLM validation pass.

## Implementation blocks

### Block A -- Internal migration engine

- Extend persisted episode source validation with `legacy-import`, while keeping public
  `episodes record` input restricted to its existing explicit sources. The new source is produced
  only by the fixture adapter. Its private immutable provenance carries only the safe fixture ID
  and canonical input hash, so a changed fixture remains detectable even after ledger loss.
- Refactor episode input normalization into a shared pure boundary. `recordEpisode` accepts an
  internal validated deterministic ID option and refuses an existing target path, preserving
  immutability for normal and migration writes.
- Add the private strict ledger, canonical fixture hashing, deterministic ID generation, matching
  existing-record recovery, and per-record idempotent result accounting.

### Block B -- Tests and contracts

- Test synthetic learning and session-summary imports, preserved timestamp/provenance, private
  permissions, path/text-free ledger, exact rerun idempotence, interrupted-ledger recovery,
  changed-input refusal, duplicate fixture refusal, malformed/secret/client rejection, generated
  workspace validation, widened modes, and symlink refusal.
- Update CLI and TUI passive episode contracts to accept the persisted provenance source while still
  rejecting text/path/body in passive state.
- Prove no public dispatcher command names an import/migration surface.

### Block C -- Audit closure documentation

- Add a maker report that repeats the metadata-only private-repository boundary and names F10 as
  the owner of public clean-install import/export documentation.
- Update ADR-008, the product program, CHANGELOG, and durable learning. State clearly that no
  real legacy data moved and independent review remains required.

## Verification matrix

- Focused migration, episode, contract, TUI parser/panel, and visible-English tests during the
  implementation blocks.
- Final `bun test ./cli/`, `bun test ./tui/test/`, dispatcher/shell syntax, diff check, zero-hex
  for TUI, English changed-surface sweep, and diff secret-pattern check.
- Use only harmless synthetic test directories. No daemon, provider request, paid call, personal
  repository content, or client repository is a test prerequisite.

## Stop conditions

Stop and return to design if a migration needs a path or raw content reader, if a ledger would
store source text or local paths, if recovery could overwrite an immutable episode, if the user
would see a public import feature before its privacy contract exists, or if a test requires private
repository or daemon access.
