# F9.2 Implementation Plan -- Episodes, Recall, and Procedures

## Implementation status

The maker implementation is complete on 2026-07-18. `docs/F9.2-EPISODES-PROCEDURES-MAKER-REPORT.md`
records the concrete contracts, local verification, and checker reproduction scope. This does not
constitute approval: the persistence and TUI boundaries remain subject to independent review before
F9 or a public release can be called ready.

## Premises verified

1. `ebrain remember` is already an explicit, secret- and client-checked user/agent write. It is
   therefore an appropriate source for a second, local immutable episode record after its existing
   durable-learning write succeeds.
2. `log-session.sh` is a fail-open stop hook. F9.2 will not add a Bun/episode dependency to that
   lifecycle-critical hook. Session-summary episode import remains explicit and fixture-only until
   F9.3.
3. Existing workflow records are versioned local copies. `run` only materializes a checklist, and
   `skillify` is y-confirmed. Lifecycle metadata must be a sidecar and may never mutate source
   Markdown, launch a shell, or pick a provider/model.
4. The current Memory TUI is already contract-driven. It can be consolidated without direct store
   reads by adding bounded CLI summary contracts and preserving the existing legacy recent rows
   during the fixture-only migration window.

## Non-goals

- No raw pane/transcript ingestion, daemon schema change, MCP write, external memory provider,
  background sync, benchmark/model request, or LLM validation pass.
- No migration of personal `agent-memory` content, CKIS vault content, or session files.
- No auto-promotion of a capture candidate, auto-archive timer, inferred task success, or provider
  recommendation.
- No new shell execution surface. Procedure operations manipulate local metadata only.

## Block A -- Immutable local episodes

### Store and schema

Add `cli/episodes.ts` with a private default store at
`~/.config/ebrain/episodes` (override only by `EBRAIN_EPISODES_DIR` for isolated tests).

Each `<opaque-id>.json` record is schema version 1 and contains only:

```text
id, kind (learning|session-summary), source (remember|explicit|harness-summary),
created_at, project, agent, optional safe session, optional generated workspace_id,
content_hash, text
```

It has no filesystem path, command, environment, credential, provider, model, terminal output,
cost, or raw input payload. The directory is `0700`; records are `0600`; writes are atomic; unknown
fields, symlinks, non-private records, invalid IDs/timestamps, oversized content, secret-shaped
text, and denied-client references fail closed.

### CLI contract

```text
ebrain episodes list [--limit N] --json
ebrain episodes get <episode-id> [--max-chars N] --json
ebrain episodes recall "query" [--limit N] --json
ebrain episodes record --kind learning|session-summary --source explicit|harness-summary \
  --project SAFE --agent SAFE [--session SAFE] [--workspace-id GENERATED] --text TEXT --yes --json
```

`list` returns summaries only. `get` is explicit and bounded. `recall` uses bounded local lexical
matching and returns summary, bounded excerpt, and explainable match count; it does not pretend to
be daemon semantic search. A clean install returns empty lists. An existing workspace reference is
validated through the strict workspace store; a path is never accepted.

### Existing write integration

After `remember.sh` successfully writes its existing learning, it invokes the episode recorder
with structured quoted values and `--yes`. That mirror is best-effort: failure emits a generic
warning but cannot invalidate the already-successful durable learning or stop a user workflow.
The episode source is `remember`. No session hook is changed in this block.

## Block B -- Reviewed procedure lifecycle

### Store and schema

Add `cli/procedures.ts` with a private metadata sidecar at
`~/.config/ebrain/procedures` (test override `EBRAIN_PROCEDURES_DIR`). The workflow record remains
the procedure content source of truth. Metadata contains an ID, `active|stale|archived` state,
bounded immutable event history, use count, last-use/review timestamps, and a workflow version
reference. `skillified` is derived from the existing local skill file, not duplicated as mutable
truth.

### CLI contract

```text
ebrain procedures list [--limit N] --json
ebrain procedures show <workflow-id> --json
ebrain procedures use <workflow-id> --yes --json
ebrain procedures review <workflow-id> --state active|stale|archived --yes --json
```

`use` is an explicit intent signal, not proof of outcome. `review` is the only lifecycle transition;
it can revive an archived/stale procedure to active. No elapsed time changes state. Both mutations
first resolve the existing safe workflow and append a bounded event. A missing workflow has no
metadata side effect.

## Block C -- Memory cockpit consolidation

Memory will remain a three-region, contour-only, six-control surface:

```text
Recall       local episode summaries first; legacy recent learnings/session summaries remain
             visible as transition signal until F9.3 fixture migration.
Context      operator/current-workspace pack identities and versions only; no pack bodies.
Procedures   workflow summaries plus lifecycle state, explicit-use evidence, and skill presence.
```

The TUI calls only `episodes list`, `context list`, and `procedures list` JSON contracts. Pack and
episode bodies are never passively stored in TUI state. Existing workflow materialization and
attach-to-Launch behavior stay unchanged. Compact layouts retain a usable Recall path at `80x24`;
all new visible text is English.

## Verification matrix

### Engine first

- Episode schema/ID/timestamp/provenance invariants, strict unknown fields, private permissions,
  symlink rejection, atomic writes, idempotence boundaries, secret/client rejection, max bounds,
  path-free list/recall, empty clean-install behavior, and workspace-ID validation.
- Direct isolated dispatcher smoke for record/list/get/recall and `remember` mirror behavior with
  no daemon requirement. The latter must preserve an existing remember success if mirroring fails.
- Procedure strict metadata tests: absent metadata defaults active, y-only use/review, no auto
  transition, state revival, missing workflow refusal, event bound, path-free output, no workflow
  content mutation, and derived skill presence.

### UI and contracts

- Zod public JSON fixtures reject paths, bodies on passive lists, unknown metadata, model/provider
  fields, malformed lifecycle states, and mismatched workspace IDs.
- TUI parsers fail closed on unexpected fields. Pure responsive frames cover `80x24`, `100x30`, and
  `160x48`, row-width invariants, no more than six footer controls, and no hidden context bodies.
- Real tmux TUI smoke uses temporary config/store directories only. No provider, daemon, client
  repository, or paid request is a prerequisite.

### Phase gate

Run focused contracts during each block, then `bun test ./cli/`, `bun test ./tui/test/`, dispatcher
syntax, zero-hex for TUI source/diff, English visible-surface sweep, whitespace, and diff secret
safety. Record a maker report, CHANGELOG entry, durable learning, one descriptive phase commit,
and explicit independent-checker reproduction instructions. Do not call the result approved.

## Stop conditions

Stop and return to design if mirroring can make `remember` fail after its existing write, if any
operation requires a path/command/environment input, if a raw transcript is needed, if a UI layout
cannot preserve Recall at `80x24`, or if lifecycle metadata becomes an autonomous scoring or
archiving system.
