# F9.3 Maker Report -- Fixture Migration and Audit Closure

## Scope delivered

F9.3 closes the migration-design and private-repository audit boundary defined by ADR-008. It does
not migrate any real data. The private `agent-memory` repository remains unread: no content,
files, commits, issues, clone, local path, or remote request was used for implementation or tests.
The only previously recorded audit was remote metadata, and the repository remains neither a
runtime dependency nor a migration source.

### Internal fixture adapter

`cli/episode-migration.ts` is an internal test-only module, deliberately absent from the `ebrain`
dispatcher and TUI. It accepts an already-materialized in-memory array of strict synthetic
fixtures. It accepts no input path, directory selector, command, environment, remote URL,
transcript, provider value, or daemon handle.

Each fixture has only `schema_version`, `fixture_id`, `kind`, `occurred_at`, `project`, `agent`,
optional safe `session`/generated `workspace_id`, and scrubbed bounded `text`. Unknown fields,
duplicate IDs, malformed identities/timestamps, secret-shaped text, denied-client references, and
unregistered workspaces fail closed before a record is accepted.

The adapter stores a `legacy-import` episode only through the shared episode normalization and
private-write boundary. Public `ebrain episodes record` keeps its original source grammar and
rejects `legacy-import`. Passive CLI/TUI summaries recognize the provenance label but continue to
exclude text, content hash, fixture metadata, and filesystem paths.

### Recovery and immutability

The adapter derives a deterministic UUID-shaped episode ID from a canonical fixture hash and uses
a `0600` atomic private ledger in a `0700` directory. Ledger entries contain only a safe fixture
ID, canonical input hash, episode ID, and import time. They contain no body text, path, command,
provider, model, source location, or secret.

Each imported episode also holds a private immutable migration relation containing only the fixture
ID and canonical hash. It is never returned by list, recall, get, or TUI contracts. This relation
allows exact recovery if the ledger write was interrupted or the ledger file is lost, and prevents
a changed fixture with the same ID from creating a second episode after ledger loss. Existing
episode records are created with no-clobber atomic linking; neither recovery nor a rerun overwrites
one.

The batch is intentionally per-record recoverable, not represented as a false cross-file
transaction. A successful episode followed by a failed ledger write is resumed by exact
provenance matching on the next explicit internal call.

## Checker focus

1. Confirm the private-repository boundary independently: F9.3 must not read, clone, copy, expose,
   or claim to have migrated `agent-memory` content.
2. Inspect the dispatcher and TUI imports: `episode-migration.ts` must remain unreachable from any
   public command/action, and `legacy-import` must remain rejected by `episodes record`.
3. Reproduce normal fixture import, repeat, ledger-file loss, and changed-fixture-after-ledger-loss.
   Verify exact records are skipped/repaired and any mismatch fails without overwrite or duplicate.
4. Inspect ledger and episode permissions and payloads. Confirm ledger contents have no text/path/
   command/provider/model/source-location field, while passive list/recall/TUI output cannot expose
   private migration provenance.
5. Re-run malformed, secret-shaped, denied-client, missing-workspace, widened-mode, and symlink
   cases. Confirm clean empty stores remain usable and no daemon is required.
6. Confirm F10, not F9.3, owns a public clean-install import/export format, documentation, license,
   website, and release claims.

This is maker evidence, not a release or independent audit verdict.
