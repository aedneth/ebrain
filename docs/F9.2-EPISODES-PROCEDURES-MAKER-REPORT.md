# F9.2 Maker Report -- Episodes, Procedures, and Memory

## Scope delivered

F9.2 implements the two local layers approved by ADR-008 without changing federation, daemon
ownership, provider selection, shell control, or the source content of existing workflows.

### Immutable local episodes

`ebrain episodes` adds a private local store for bounded, scrubbed, immutable recall records:

```text
ebrain episodes list [--limit N] --json
ebrain episodes get <episode-id> [--max-chars N] --json
ebrain episodes recall "query" [--limit N] --json
ebrain episodes record --kind learning|session-summary --source remember|explicit|harness-summary \
  --project <safe-label> --agent <safe-label> [--session <safe-id>] \
  [--workspace-id <generated-id>] --text <text> --yes --json
```

Records are `0600` in a `0700` local directory and are written with atomic replacement. An episode
has an opaque ID, kind/source, timestamp, safe project/agent/session/workspace provenance, content
hash, and scrubbed text. It does not carry a path, command, environment, provider, model, cost, or
raw terminal transcript. Unknown fields, non-private stores, symlinks, malformed IDs/timestamps,
secret-shaped text, denied-client references, and unknown workspace identities fail closed.

`list` exposes summaries only. `get` is explicit and bounded; `recall` is a bounded local lexical
match with a bounded excerpt and explainable term count. Neither pretends to be daemon semantic
retrieval. After the existing durable-learning write succeeds, `ebrain remember` mirrors it as a
`remember` episode best-effort. The mirror has no authority to fail the already-committed learning.

### Reviewed procedures

`ebrain procedures` attaches human-reviewed lifecycle evidence to existing normalized workflow
records while keeping those records as the only procedure-content source of truth:

```text
ebrain procedures list [--limit N] --json
ebrain procedures show <workflow-id> --json
ebrain procedures use <workflow-id> --yes --json
ebrain procedures review <workflow-id> --state active|stale|archived --yes --json
```

Private metadata records are atomic and contain only the workflow ID, lifecycle state, explicit use
count, bounded event tail, and review/use timestamps. `use` is an intentional-use signal, not a
success result. Only `review` changes lifecycle state; no elapsed-time job archives a procedure.
An explicit review can revive `stale` or `archived` to `active`. Skill presence is derived from the
existing local `SKILL.md` rather than duplicated as mutable metadata. Procedure operations neither
run a workflow or shell command nor select a provider/model.

### Memory cockpit

The Memory tab remains a contour-only, three-focus-region surface:

```text
Recall       episode summaries first, then legacy recent learnings during F9.3 transition
Context      pack identities and versions only; no body, focus, or action
Procedures   workflow summaries with reviewed state, explicit-use count, and derived skill marker
Legacy logs  existing session summaries, visibly labelled until fixture-only migration completes
```

The TUI requests only `episodes list`, `context list`, and `procedures list` for these new layers.
It stores no episode or context body, filesystem path, procedure event, workflow source path,
command, provider, or model. Opening an episode displays provenance and tells the user that text
requires explicit bounded retrieval. Existing Enter and `a` behavior for a procedure still
materializes or attaches the underlying workflow prompt; it does not execute it.

## Checker focus

An independent checker should reproduce the following before approving F9 persistence work:

1. Verify every episode public list/recall response is path-free and body-free, while explicit get
   is character bounded. Attempt malformed records, widened modes, a symlink, secret-shaped text,
   denied-client text, and an unregistered workspace ID.
2. Verify a failed episode mirror leaves `ebrain remember` successful and its original durable
   learning intact. Verify the mirror never changes the daemon/write-through result.
3. Verify procedure `use` cannot imply task success or mutate lifecycle state; only explicit
   reviewed transitions may archive, stale, or revive a procedure. Confirm workflow Markdown and
   skill content remain untouched and derived skill presence cannot be forged in metadata.
4. Inspect `refreshMemory` and parsers: the TUI must call only summary contracts for episodes,
   context, and procedures; it must reject unexpected body/path/event/command/model/provider
   fields and render only episode provenance on Enter.
5. Reproduce Memory at `80x24`, `100x30`, and a normal terminal; check exact row widths, English
   labels, visible focus progression Recall -> Procedures -> legacy logs, and no overlap between a
   procedure title and lifecycle metadata.
6. Confirm no change weakens workspace revalidation, session confirmation, the RAM governor,
   daemon single-writer ownership, default-deny federation, or clean-install local behavior.

This is maker evidence, not a release or audit verdict.
