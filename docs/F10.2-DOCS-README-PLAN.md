# F10.2 Implementation Plan -- Public Docs, README, and Assets

## Scope

Build a new English public documentation surface for a plug-and-play developer. It will be
separate from historical operator artifacts, linked only through an explicit public-doc index, and
bounded by the F10.0 claim matrix. This phase creates local files and assets only. It does not make
existing history safe for public visibility, publish a package, create a release, or deploy a site.

## Information architecture

```text
README.md                         outcome, five-minute proof, current boundaries
assets/                           native pixel wordmark + generated sanitized TUI capture
docs/PUBLIC-DOCUMENTATION.md      public-doc allowlist and navigation root
docs/getting-started/             install, first memory, workspace/session
docs/concepts/                    memory, workspaces, procedures, costs
docs/architecture/                daemon/federation, CKIS relationship, ADR index
docs/guides/                      supported agents, routing, privacy, migration, troubleshooting
docs/reference/                   CLI, MCP, configuration, JSON-contract boundaries
docs/release/                     contribution, security, license, Devpost/release evidence
```

The README and any later website may link only to this tree, root contribution/security/license
files, and third-party notices. Historical documents are not deleted or treated as public-safe by
this phase; F10.0's release blocker remains active.

## Asset contract

1. `assets/ebrain-wordmark.svg` derives from the existing TUI pixel matrix, with the same teal
   `e` and neutral `brain`; it is a product identity asset, not a generic illustration.
2. `assets/ebrain-tui-demo.svg` is generated from the production pure frame renderer and a
   repository-owned, sanitized fixture. It contains no local path, prompt, token, client identity,
   session output, provider credential, or live telemetry.
3. A deterministic generator and test validate the asset source, expected labels, no ANSI, no
   secret-shaped content, and no private path. Generated SVG is committed for GitHub/website use.

## README requirements

- First viewport: native wordmark, one-line outcome, AGPL badge, and sanitized real TUI capture.
- Source-first quickstart: clone/install, `ebrain up`, a first durable learning, recall, and cockpit
  open. The unverified remote one-liner is not presented as a completed public-release guarantee.
- Explain daemon/MCP, optional federation and CKIS relationship, workspace/session workflow,
  governed routing, factual token costs, privacy controls, supported agents, limitations/roadmap,
  contribution, notices, and AGPL terms.
- No emojis, personal filesystem paths, customer/client identity, secret value, universal model
  ranking, subscription-cost claim, or unsupported always-on/embedded-shell claim.

## Verification

- Add a docs/asset contract test that verifies all public-doc links resolve, required README claims
  map to F10.0, no public navigation crosses into historical paths, all generated assets are
  present and sanitized, and public-copy forbidden patterns are absent.
- Run focused docs/asset plus CLI/TUI suites, shell syntax, diff check, zero-hex, and diff-secret
  scans. Inspect Markdown links without following remote URLs.
- The maker report must distinguish local documentation completion from the still-pending
  public-history/isolation remediation and independent review.

## Stop conditions

Stop if a desired public page needs historical/private content, a claim lacks F10.0 evidence, a
generated asset cannot be proven sanitized, an asset would require an external service, or docs
would imply that publishing/deploying has occurred. Do not paper over a privacy blocker by simply
removing it from navigation.
